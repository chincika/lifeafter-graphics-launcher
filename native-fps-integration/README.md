# 游戏内帧率选项集成

自动适配目前支持两套已审查的原始模块：老 PC 20261001 和发烧平台 20261022。游戏包中其他记录或目标槽的位置变化时，启动器可解析当前索引并重新生成四档；目标模块自身发生变化或来源无法确认时仍会锁定。支持范围、更新后的操作和恢复边界见 [自动适配说明](AUTO-ADAPTATION.zh-CN.md)。

主界面一次安装游戏内的 180、240、300、360 四档，原有 120 及低帧档位保留。游戏内保存的索引分别是 180→8、240→7、300→9、360→10；240 延用实验版的索引 7。选择启动器的 120 画质预设时会保留游戏内已保存的新增高帧档，25/60 预设继续应用各自的帧数。

旧版 120 帧接管保留在“工具 → 开发者选项”，仅支持其原有的 180、240、300 档。旧版自动适配档案可以从原启动器数据目录继续读取，新增档案保存在游戏目录。两种模式不能同时写入：切换模式前要先使用当前模式的恢复按钮。原有免责声明与后端写入门禁仍然生效。

自动适配安装和恢复会在游戏根目录的 `帧率解锁备份/游戏内档位/` 新建独立事务目录，保存修改前的完整 lc 包和原始槽并校验哈希；帧率数据表所在的 py3 包保持只读。恢复时，已验证的新增档位配置会先备份，再回退到 120。原有精确匹配的 240 实验版升级流程保留。旧模式的新还原点位于游戏根目录下 `帧率解锁备份/接管模式/`，旧模式事务备份位于 `Documents/fps_unlock_backups/`。备份不会覆盖已有文件。

## 构建和验证

- `desktop-app/build-backend.ps1` 编译后端并更新运行组件清单中的 SHA-256。旧版恢复资源和逐函数适配契约嵌入后端；自动适配不内置完整的新游戏模块。
- `build_v04.py` 从 `patches/*.original.bin` 重新生成记录到 `generated/`，不修改游戏。它使用工作区内 `current-npk-fps-analysis` 的 CPython 3.14 和 LZ4 依赖；生成结果应与 `patches/*.v04.bin` 哈希一致。
- `test_v04_semantics.py` 使用 CPython 3.14 和只读数据表模拟运行实际重写后的函数，覆盖四档、原档、选项点击、帧预测和重启读取。
- `test_backend.py` 在完整包体副本上检查安装、升级、备份、恢复、冲突与未知数据拒绝。它读取本机实验室的原版包体备份，并使用已同意的本机免责声明记录，不触碰实际游戏文件。
- `test_adaptive.py` 在两套完整包体副本上测试适配、重复启用、隔离语义、未完成更新、帧率表变化、未知模块、重复或缺失记录、中断恢复和跨版本恢复拒绝。
- 桌面程序执行 `npm test` 和 `ui-screenshot-smoke.js`。在 `desktop-app` 下运行 `npx electron-builder --win portable` 可构建便携版。

已在本机确认四档在游戏中显示、游戏能够进入场景。实际性能取决于设备和场景；单凭档位显示不能证明所有场景都能达到标注的帧数。
