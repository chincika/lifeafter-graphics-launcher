# 公告发布流程

以下命令在 PowerShell 执行，先进入项目根目录：

```powershell
Set-Location 'C:\Users\Admin\Documents\一键启动\v2.4.0-system-core-fix'
New-Item -ItemType Directory -Path release-operations/generated -Force
gh release download launcher-notices --repo chincika/lifeafter-graphics-launcher --pattern notices.json --dir release-operations/generated --clobber
node -e 'const fs=require("fs");const e=JSON.parse(fs.readFileSync("release-operations/generated/notices.json","utf8"));console.log(Buffer.from(e.payload,"base64").toString("utf8"));'
```

该解码命令只用于查看内容，不代表签名已验证。正式客户端会验证签名。

## 编辑原始清单

复制 `notice-template.json` 为 `generated/notice-source.json`，编辑后再签名。不要覆盖下载文件后误把原始 JSON 当成签名封装上传。

- sequence 必须大于远端当前 sequence；不要重复使用。
- 保留当前 updatePolicy，除非有意变更或撤销强制更新。
- 保留仍需展示的现有 messages：清单是全量替换，不是追加接口。
- id 是稳定唯一编号；version 是该公告的内容版本。
- type：notice 普通公告；risk 风险提示；disclaimer 需要勾选同意，并限制新增帧率应用。
- title、body 是纯文本，不支持脚本、HTML 执行或可执行附件。
- minVersion/maxVersion 可限定程序版本；startsAt/expiresAt 使用含时区的 ISO 时间，expiresAt 必填。
- 内容改变会要求重新确认；普通公告确认后不重复，稍后处理后本次运行不再自动弹出。

## 签名、上传

```powershell
node desktop-app/sign-notices.js release-operations/generated/notice-source.json |
  Set-Content -LiteralPath release-operations/generated/notices.json -Encoding ascii
gh release upload launcher-notices release-operations/generated/notices.json --repo chincika/lifeafter-graphics-launcher --clobber
```

签名封装由 payload 和 signature 两字段组成。只上传签名文件；不得上传私钥。

## 验证

查看 GitHub 公告 Release，确认附件名为 notices.json、上传成功。重新下载到其他目录，与本地签名文件比较 SHA-256；相同只证明上传一致，还需用客户端验证签名与行为。

启动现代版，保持窗口可见且有焦点，等待后台检查和界面的下一轮展示（通常需额外最多约 30 秒）。工具页“查看公告”可重新查看已经下载的有效公告，但不会主动刷新网络。

测试普通公告确认不重复、稍后处理、版本筛选及过期；免责声明测试不同意不能新增解锁但仍可恢复。不要为测试而实际修改游戏文件。

网络断开、签名错误时保留最后一次验证通过的缓存。托盘、失焦或忙碌时不会强行弹出；一分钟轮询不是保证一分钟送达。

撤回公告：从全量 messages 中移除，并用更大的 sequence 重发。客户端在线获取后生效；离线端仍可能使用之前的有效缓存。
